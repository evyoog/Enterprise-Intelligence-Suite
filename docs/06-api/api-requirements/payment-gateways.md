# API requirements — Payment gateways (module `billing`)

Requirement: [REQ-BIL-003](../../02-requirements/FRD/payment-gateways/requirement.md) (Approved, [C98](../../01-business/roadmap/open-decisions.md#c98); administrator-added gateways [C99](../../01-business/roadmap/open-decisions.md#c99), REQ-BIL-003.16 and .17). Rules: [business-rules.md](../../02-requirements/FRD/payment-gateways/business-rules.md) (BR-n below). Standard REST verbs ([C14](../../01-business/roadmap/open-decisions.md#c14)); the OpenAPI contract is generated by springdoc into `../openapi/` once built. Code: `AdminPaymentGatewayController`, `PaymentWebhookController`, `GatewayManagementService`, `GatewayRoutingService`, `PaymentService`, `GatewayDtos`.

**No response ever carries a secret** (BR-4). A configuration field says only whether it is set, where its value comes from and, for a non-secret identifier, a masked form.

## Security
| Path | Authentication | Permission |
|---|---|---|
| `/admin/billing/gateways/**` (and the earlier `/admin/billing/gateway`, `/admin/billing/gateway/test`) | Keycloak JWT | Platform permission **`MANAGE_BILLING`**, enforced in `SecurityConfig` for every path under `/admin/billing`. No token: 401. Signed in without the permission: 403. |
| `POST /webhooks/{provider}` | **None** (permitted without a user token) | Trusted only through the provider's signature on the raw body (BR-12) |

Only `MANAGE_BILLING` can add, edit or remove a gateway and enter, replace or rotate credentials. Credentials are stored AES-256-GCM encrypted with the master key `PAYMENT_GATEWAY_ENCRYPTION_KEY` (BR-3).

`{code}` in a path is the provider code, **case-insensitive** (`razorpay` and `RAZORPAY` are the same). An unknown code is 404 "Payment gateway not found".

## Shapes
`Gateway` (one list row; `GET /gateways`, `PUT /gateways/default`; also `Detail.gateway`):
```json
{
  "code": "RAZORPAY",
  "name": "Razorpay",
  "description": "Cards, UPI, netbanking and wallets for payments in India and, where enabled on your account, abroad.",
  "logo": "razorpay",
  "implementation": "IMPLEMENTED",
  "custom": false,
  "supportedMethods": ["card", "upi", "netbanking", "wallet"],
  "enabledMethods": ["card", "upi", "netbanking", "wallet"],
  "currencies": ["USD", "EUR", "GBP", "INR"],
  "countries": ["IN"],
  "environment": "TEST",
  "configurationStatus": "CONFIGURED",
  "connectionStatus": "CONNECTION_SUCCESSFUL",
  "connectionMessage": "Razorpay accepted the credentials.",
  "testedAt": "2026-10-14T09:15:00Z",
  "activated": true,
  "defaultGateway": true,
  "actions": { "configure": true, "test": true, "activate": false, "deactivate": true, "setDefault": false, "edit": false, "remove": false }
}
```
- `implementation`: `IMPLEMENTED` (a working adapter exists: Razorpay) or `CONFIGURATION_ONLY` (added by an administrator, no adapter, BR-23); `custom` is true for the latter. For a configuration-only gateway `activated` and `defaultGateway` are always false, `connectionStatus` is `NOT_TESTED` once configured (else its configuration status) with the message "No payment integration exists for this gateway, so it cannot be tested or activated.", and `actions` has only `configure`, `edit` and `remove` true (`configure` always; `test`, `activate`, `deactivate` and `setDefault` false). There is no `PLANNED` value and no `NOT_AVAILABLE` status any more.
- `configurationStatus`: `NOT_CONFIGURED`, `CONFIGURATION_INCOMPLETE`, `CONFIGURED`.
- `connectionStatus`: `NOT_CONFIGURED`, `CONFIGURATION_INCOMPLETE`, `NOT_TESTED`, `CONNECTION_SUCCESSFUL`, `AUTHENTICATION_FAILED`, `PROVIDER_UNAVAILABLE`, `UNSUPPORTED_CONFIGURATION`, `TEST_FAILED`. `NOT_TESTED` also means "the configuration changed since the last test" (BR-6). `connectionMessage` and `testedAt` are present only when a test result applies.
- `actions` says which buttons are valid: `configure` (always), `test` (implemented and configured), `activate` (implemented, configured and not active), `deactivate` (implemented and active), `setDefault` (implemented, active and not default), `edit` and `remove` (only an added gateway).
- `currencies` are the currencies the provider can take (Razorpay: every currency EIS supports, USD, EUR, GBP and INR); `enabledMethods` is the subset switched on (BR-15). Enum fields are returned as the strings shown.

`Summary`: `{ "registered": 3, "implemented": 1, "configured": 2, "active": 1, "needsConfiguration": 1 }`: `registered` counts every gateway (added ones included), `implemented` counts adapters only, `configured` every gateway whose configuration status is `CONFIGURED`, `active` only gateways accepting payments and `needsConfiguration` **every gateway** that is not `CONFIGURED` (BR-23).

`Detail` (`GET /gateways/{code}` and the result of configure, activate, deactivate and methods):
```json
{
  "gateway": { "…": "a Gateway, as above" },
  "transactionTypes": ["INVOICE_PAYMENT"],
  "environments": ["TEST", "LIVE"],
  "webhookSupport": true,
  "refundSupport": true,
  "recurringSupport": false,
  "fields": [
    { "key": "keyId", "label": "Key ID", "secret": false, "required": true, "webhook": false,
      "help": "Starts with rzp_test_ for the Test environment or rzp_live_ for Live.",
      "configured": true, "source": "ENVIRONMENT", "maskedValue": "rzp_test_••••••7890" },
    { "key": "keySecret", "label": "Key secret", "secret": true, "required": true, "webhook": false,
      "help": "Shown once in the Razorpay Dashboard when the key is created.",
      "configured": true, "source": "STORED", "maskedValue": null },
    { "key": "webhookSecret", "label": "Webhook secret", "secret": true, "required": true, "webhook": true,
      "help": "The secret you enter when you add the webhook in the Razorpay Dashboard.",
      "configured": false, "source": "NONE", "maskedValue": null }
  ],
  "setupSteps": ["In the Razorpay Dashboard, create a Test key (or a Live key when you go live).", "…"],
  "webhook": {
    "url": "https://eis.evyoog.com/api/webhooks/razorpay",
    "supported": true,
    "secretConfigured": false,
    "signatureStatus": "NOT_SEEN",
    "lastEventAt": null, "lastEventType": null,
    "failureCount": 2, "lastFailureAt": "2026-10-14T08:00:00Z", "lastFailureReason": "The webhook signature did not verify.",
    "events": ["payment.captured", "payment.failed", "refund.processed"],
    "reachableFromInternet": true
  },
  "evidence": { "authenticated": true, "webhookReceived": false, "paymentCaptured": true, "refundMade": false },
  "configVersion": 3,
  "credentialsUpdatedAt": "2026-10-14T09:10:00Z",
  "encryptionAvailable": true,
  "credentialsUnreadable": false,
  "recentEvents": [ { "eventType": "payment.captured", "receivedAt": "2026-10-14T09:20:00Z", "processedAt": "2026-10-14T09:20:00Z", "paymentId": 17 } ],
  "history": [ { "at": "2026-10-14T09:10:00Z", "action": "PAYMENT_GATEWAY_CONFIGURED", "actor": "keycloak-sub", "detail": "Configuration saved (changed: keySecret)" } ]
}
```
- `fields` are the provider's configuration fields in order. `source` is `STORED` (saved on the screen), `ENVIRONMENT` (environment or secrets file) or `NONE`. `maskedValue` is **always null for a secret field**, and null when not set. `webhook: true` marks the field the adapter uses to verify webhooks.
- `webhook.url` is `app.backend-url` (environment variable `BACKEND_URL`) + `/webhooks/{code in lower case}`. `signatureStatus`: `VERIFIED` (a correctly signed event was accepted), `NOT_SEEN`, `NOT_APPLICABLE`. `reachableFromInternet` is false when the host is `localhost`, a loopback or `.local` address. `failureCount` counts rejected deliveries since the row was created (BR-13).
- `evidence` comes from real records, not from the connection test (BR-16). `recentEvents` is the last 20 events of this provider (the screen shows 8); `history` the last 10 administrator changes (BR-19), newest first.
- `encryptionAvailable` is false when the master key is not set (BR-3); `credentialsUnreadable` is true when ciphertext is stored that the current key cannot read.
- For an added (configuration-only) gateway `fields` are the credential fields of its definition (with `help` and `webhook` empty or false), `transactionTypes` is `["INVOICE_PAYMENT"]`, `environments` is `["TEST","LIVE"]`, `webhookSupport`, `refundSupport` and `recurringSupport` are false, `setupSteps` and `webhook.events` are empty, `webhook.signatureStatus` is `NOT_APPLICABLE`, and `webhook.url` is only the address an endpoint would have (it answers 404 because no adapter exists).

`Connection` (`POST /gateways/{code}/test`): `{ "status": "AUTHENTICATION_FAILED", "message": "Razorpay refused the credentials (HTTP 401).", "testedAt": "2026-10-14T09:15:00Z", "successful": false }`. For `NOT_CONFIGURED` and `CONFIGURATION_INCOMPLETE` the provider is not called, nothing is stored and no audit entry is written.

`SaveConfiguration` (`PUT …/configuration`): `{ "environment": "TEST", "fields": { "keyId": "rzp_test_…", "keySecret": "…" } }`. `environment` (TEST or LIVE, case-insensitive; omitted or blank keeps the current one) and `fields` (field key → value; blank values are ignored and keep the stored value). Each value is trimmed, at most 500 characters, no control characters. Every successful save increases `configVersion`.

`SetMethods` (`PUT …/methods`): `{ "methods": ["card", "upi"] }` (case-insensitive; duplicates ignored). `SetDefault` (`PUT /gateways/default` and `/gateways/active`): `{ "code": "RAZORPAY" }`.

## Gateways added by an administrator (C99)
Rules BR-20 to BR-25 in [business-rules.md](../../02-requirements/FRD/payment-gateways/business-rules.md). An added gateway has no adapter: it stores configuration and credentials and nothing else (`implementation` `CONFIGURATION_ONLY`). **To make one take payments a developer must write an adapter** ([09-integrations/payment-gateways.md](../../09-integrations/payment-gateways.md#how-to-turn-an-added-gateway-into-a-real-integration)).

`Definition` (the body of `PUT …/{code}/definition`, and `definition` in the add request; **never a secret**):
```json
{
  "code": "STRIPE",
  "name": "Stripe",
  "description": "Cards and local payment methods worldwide.",
  "logo": "stripe",
  "countries": ["US", "IN"],
  "currencies": ["USD", "EUR", "INR"],
  "methods": ["card", "wallet"],
  "fields": [
    { "key": "publishableKey", "label": "Publishable key", "secret": false, "required": true },
    { "key": "secretKey", "label": "Secret key", "secret": true, "required": true }
  ]
}
```
`CreateGateway` (`POST /admin/billing/gateways`): `{ "definition": { … }, "environment": "TEST", "values": { "publishableKey": "pk_test_…", "secretKey": "sk_test_…" } }`. `environment` is `TEST` (default when omitted or blank) or `LIVE`; `values` is optional (field key to value; blank values are ignored). The response is the `Detail` of the new gateway, status **201**.

| Rule | Limit |
|---|---|
| `code` | `^[A-Z][A-Z0-9_]{1,29}$` after upper-casing; not `DEFAULT`, `ACTIVE`, `SUMMARY`, `TEMPLATES`; not a built-in adapter code; not an existing code (409). Ignored on edit (the code never changes) |
| `name` | Required, up to 100 characters |
| `description` | Optional, up to 300 characters |
| `logo` | Optional key `^[a-z0-9_-]{1,30}$`; an invalid or empty key is replaced by the lower-case code. An unknown key shows a neutral monogram |
| `currencies` | At least 1, up to 20, three letters each (upper-cased, duplicates ignored) |
| `countries` | Optional, up to 50, two letters each |
| `methods` | At least 1 of `card`, `upi`, `netbanking`, `wallet`, `bank_transfer`, `paypal` (lower-cased, duplicates ignored) |
| `fields` | 1 to 12; `key` `^[A-Za-z][A-Za-z0-9]{0,39}$` and unique ignoring case; `label` 1 to 60 characters; at least one `required` |
| `values` | Each key must be a field key (400 "Unknown field: …"); trimmed, up to 500 characters, no control character; saved encrypted. Any value needs `PAYMENT_GATEWAY_ENCRYPTION_KEY` (409 otherwise) |

Other points:
- **Nothing is saved on a refusal** (400 validation, 409 duplicate or no key). A duplicate is checked before the insert and again by the unique constraint on `provider_code` (a race answers 409 too).
- **`PUT …/{code}/definition`** replaces the definition of an added gateway (the `code` in the body is ignored): stored values of fields that no longer exist are dropped, the others are kept, the payment-method switches reset, `configVersion` increases and the environment is kept. A built-in provider answers 409 "{name} is a built-in provider; its definition cannot be changed or removed."
- **Values later:** `PUT …/{code}/configuration` ([BR-22](../../02-requirements/FRD/payment-gateways/business-rules.md)) works for an added gateway: typed fields are stored encrypted, blank ones keep the stored value, the environment can change, and no connection test runs.
- **`DELETE …/{code}`** answers 204, deletes the row and its ciphertext, and is audited. Built-in provider: 409; unknown code: 404.
- **`Template`** (`GET …/templates`): `{ "code", "name", "description", "logo", "countries", "currencies", "methods", "fields": [{ "key", "label", "secret", "required" }] }`, no values; the Add form copies it into a `Definition`. A template is not a gateway: it has no status and is not routed to.
- **No response carries a value** (BR-22): a field shows `configured`, `source` `STORED` and, for a non-secret field, `maskedValue`; `maskedValue` is always null for a secret.

## Errors (gateway endpoints)
| Status | Code | When |
|---|---|---|
| 400 | (validation) | Add or edit definition: any rule of the table in [Gateways added by an administrator](#gateways-added-by-an-administrator-c99) broken (code, name, description, currencies, countries, methods, fields, environment); unknown field key ("Unknown field: …"); a value over 500 characters or with a control character ("{label} is not valid."); an environment the provider does not offer ("Environment must be one of TEST, LIVE."); Razorpay Key ID prefix wrong or not matching the environment (BR-14); methods empty or not supported by the provider |
| 401 | — | No token |
| 403 | — | Signed in without `MANAGE_BILLING` |
| 404 | `NOT_FOUND` | Unknown provider code |
| 409 | `INVALID_STATE` | Add: the code is a built-in adapter code or already exists ("A payment gateway with the code … already exists."); edit or remove a built-in provider ("… is a built-in provider; its definition cannot be changed or removed."); the gateway has **no payment integration** ("{name} has no payment integration in EIS, so it can store credentials but cannot be tested, activated or used for payments." — test, activate, deactivate, methods, default; configure is allowed); credentials entered but the server has no encryption key; activate on a gateway that is not fully configured ("… is not fully configured yet."); activate when the connection test fails ("… was not activated: {message}"); a rotation whose test fails ("Not saved: {status}: {message} The previous configuration is unchanged."); default on a gateway that is not active ("Only an active gateway can be the default.") |

## Webhook endpoint
| Method | Path | Authentication | Purpose |
|---|---|---|---|
| POST | `/webhooks/{provider}` | None. The provider's signature header, verified by that provider's adapter against the **raw body** | Receive the provider's payment and refund events |

- `{provider}` is the provider code in any case. Today only `/webhooks/razorpay` exists (a gateway an administrator added has no webhook endpoint, BR-23) (the URL is unchanged from [REQ-BIL-001](../../02-requirements/FRD/billing-payments/requirement.md)): header `X-Razorpay-Signature`, events `payment.captured`, `payment.failed`, `refund.processed`.
- **200**, empty body: the event was accepted and processed, or was a repeat of an event already processed for that provider (acknowledged so the provider stops retrying), or an event type nobody subscribed to (recorded and ignored).
- **400 `SIGNATURE_INVALID`**: the signature is missing or does not verify, the provider is not fully configured, or the body cannot be understood. Nothing is changed; one failure is counted on the gateway (BR-13).
- **404**: the provider is unknown, or is a gateway an administrator added (no adapter; not counted).
- Idempotent **per provider and event id** (unique on `payment_webhook_event(provider, provider_event_id)`, V038). Accepted for a configured provider even if it is deactivated (BR-13).
- Setting it up per provider: [09-integrations/payment-gateways.md](../../09-integrations/payment-gateways.md#registering-the-webhook-per-provider).

## Changes to the customer payment endpoints
| Endpoint | Change |
|---|---|
| `POST /me/billing/invoices/{invoiceId}/payments` and the organization twin | The backend **routes** the payment (BR-10), using the optional body `method` (`card`, `upi`, `netbanking`, `wallet`). **No eligible gateway: 503 `PAYMENT_GATEWAY_NOT_CONFIGURED`**, message "No payment gateway is available for {currency} {method} payments."; nothing is created. The response gains **`provider`** (the code of the gateway chosen) and **`clientConfig`** (a string map of everything public the browser needs to open that provider's window; never a secret). `keyId` is kept (Razorpay Checkout's public key) and equals `clientConfig.keyId`. |
| `POST /me/billing/payments/{paymentId}/confirm` | Request unchanged. The result is verified by **the payment's own provider** (BR-11); 503 if that provider's credentials are no longer complete. |
| `POST /admin/billing/payments/{paymentId}/refunds` and `/reconcile` | Request unchanged; sent to the payment's own provider. |
| `GET /me/billing/checkout` | `gatewayConfigured` is true when some gateway can take the invoice's currency; `gatewayCode` and `gatewayName` name the gateway that would be used first (default first); the offered methods are those Billing settings allow and an eligible gateway offers (BR-15). |

## Audit actions
`PAYMENT_GATEWAY_CONFIGURED`, `PAYMENT_GATEWAY_CONFIGURATION_REJECTED`, `PAYMENT_GATEWAY_TESTED`, `PAYMENT_GATEWAY_ACTIVATED`, `PAYMENT_GATEWAY_DEACTIVATED`, `PAYMENT_GATEWAY_DEFAULT_CHANGED`, `PAYMENT_GATEWAY_METHODS_CHANGED`, and since C99 `PAYMENT_GATEWAY_ADDED`, `PAYMENT_GATEWAY_DEFINITION_CHANGED`, `PAYMENT_GATEWAY_REMOVED` — target type `PaymentGateway`, target id the provider code; the detail never contains a credential value (BR-19).
