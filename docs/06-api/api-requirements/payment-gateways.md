# API requirements — Payment gateways (module `billing`)

Requirement: [REQ-BIL-003](../../02-requirements/FRD/payment-gateways/requirement.md) (Approved, [C98](../../01-business/roadmap/open-decisions.md#c98)). Rules: [business-rules.md](../../02-requirements/FRD/payment-gateways/business-rules.md) (BR-n below). Standard REST verbs ([C14](../../01-business/roadmap/open-decisions.md#c14)); the OpenAPI contract is generated by springdoc into `../openapi/` once built. Code: `AdminPaymentGatewayController`, `PaymentWebhookController`, `GatewayManagementService`, `GatewayRoutingService`, `PaymentService`, `GatewayDtos`.

**No response ever carries a secret** (BR-4). A configuration field says only whether it is set, where its value comes from and, for a non-secret identifier, a masked form.

## Security
| Path | Authentication | Permission |
|---|---|---|
| `/admin/billing/gateways/**` (and the earlier `/admin/billing/gateway`, `/admin/billing/gateway/test`) | Keycloak JWT | Platform permission **`MANAGE_BILLING`**, enforced in `SecurityConfig` for every path under `/admin/billing`. No token: 401. Signed in without the permission: 403. |
| `POST /webhooks/{provider}` | **None** (permitted without a user token) | Trusted only through the provider's signature on the raw body (BR-12) |

Only `MANAGE_BILLING` can enter, replace or rotate credentials. Credentials are stored AES-256-GCM encrypted with the master key `PAYMENT_GATEWAY_ENCRYPTION_KEY` (BR-3).

`{code}` in a path is the provider code, **case-insensitive** (`razorpay` and `RAZORPAY` are the same). An unknown code is 404 "Payment gateway not found".

## Gateway endpoints (`MANAGE_BILLING`)
| Method | Path | Purpose | Success | Errors |
|---|---|---|---|---|
| GET | `/admin/billing/gateways` | **List every registered provider** (implemented and planned) as `Gateway` rows, implemented providers by code, then the planned ones | 200 `Gateway[]` | 401, 403 |
| GET | `/admin/billing/gateways/summary` | Overview counts for the page header | 200 `Summary` | 401, 403 |
| GET | `/admin/billing/gateways/{code}` | **Details** of one provider (also for a planned one): capabilities, configuration fields with set / source / mask, set-up steps, webhook, evidence, recent webhook events, change history | 200 `Detail` | 401, 403, 404 |
| PUT | `/admin/billing/gateways/{code}/configuration` | **Save the environment and credentials.** A blank or absent field keeps the stored value. An active gateway is re-tested in the same request (BR-9) | 200 `Detail` | 400, 401, 403, 404, 409 |
| POST | `/admin/billing/gateways/{code}/test` | **Test the connection** with the credentials in force; stores and returns the outcome (BR-7) | 200 `Connection` (also when the test fails: read `status` and `successful`) | 401, 403, 404, 409 (planned) |
| POST | `/admin/billing/gateways/{code}/activate` | **Activate** after a fresh passing test (BR-8) | 200 `Detail` | 401, 403, 404, 409 |
| POST | `/admin/billing/gateways/{code}/deactivate` | **Deactivate**; also clears the default; always allowed for an implemented provider | 200 `Detail` | 401, 403, 404, 409 (planned) |
| PUT | `/admin/billing/gateways/{code}/methods` | **Switch payment methods** on or off for this gateway (BR-15) | 200 `Detail` | 400, 401, 403, 404, 409 (planned) |
| PUT | `/admin/billing/gateways/default` | **Make a gateway the default** for new payments; body `{"code": "RAZORPAY"}` | 200 `Gateway[]` (the refreshed list) | 401, 403, 404, 409 |
| PUT | `/admin/billing/gateways/active` | **Alias of `/gateways/default`** kept from [C97](../../01-business/roadmap/open-decisions.md#c97) BI-8; same body and behaviour, and it now means "make default" (the gateway must be active, BR-8). The C97 response shape (`configured`, `active`, `methods`, `status`) is gone: it returns `Gateway[]` | 200 `Gateway[]` | as above |

Replaced from C97: `GET /admin/billing/gateways` (new row shape) and `POST /admin/billing/gateways/{code}/test` (now returns the outcome instead of an empty 200 and no longer fails with the provider's error: a failed test is a normal 200 with `successful: false`). The audit action `BILLING_ACTIVE_GATEWAY_CHANGED` is replaced by `PAYMENT_GATEWAY_DEFAULT_CHANGED`.

### Earlier Razorpay endpoints (still present)
| Method | Path | Purpose |
|---|---|---|
| GET | `/admin/billing/gateway` | Razorpay status as before: `provider`, `configured`, `liveMode`, `maskedKeyId`, `keySecretSet`, `webhookSecretSet`, `webhookUrl`, last webhook time and type. Reads the credentials in force (stored over environment); never a secret |
| POST | `/admin/billing/gateway/test` | Razorpay connection test as before: 200 with no body when Razorpay accepts the credentials; 503 `PAYMENT_GATEWAY_NOT_CONFIGURED` when a credential is missing; 502 `PAYMENT_GATEWAY_ERROR` when Razorpay refuses. It does not store a result or write an audit entry; the new screen uses `/gateways/{code}/test` |

## Shapes
`Gateway` (one list row; `GET /gateways`, `PUT /gateways/default`; also `Detail.gateway`):
```json
{
  "code": "RAZORPAY",
  "name": "Razorpay",
  "description": "Cards, UPI, netbanking and wallets for payments in India and, where enabled on your account, abroad.",
  "logo": "razorpay",
  "implementation": "IMPLEMENTED",
  "supportedMethods": ["card", "upi", "netbanking", "wallet"],
  "enabledMethods": ["card", "upi", "netbanking", "wallet"],
  "currencies": ["USD", "EUR", "GBP", "INR"],
  "countries": ["IN"],
  "environment": "TEST",
  "configurationStatus": "CONFIGURED",
  "connectionStatus": "CONNECTION_SUCCESSFUL",
  "connectionMessage": "Razorpay accepted the credentials.",
  "testedAt": "2026-10-14T09:15:00Z",
  "activated": true,
  "defaultGateway": true,
  "actions": { "configure": true, "test": true, "activate": false, "deactivate": true, "setDefault": false }
}
```
- `implementation`: `IMPLEMENTED` or `PLANNED`. For a planned provider `configurationStatus` is `NOT_AVAILABLE`, `environment` is absent, `activated` and `defaultGateway` are false and every `actions` flag is false.
- `configurationStatus`: `NOT_AVAILABLE`, `NOT_CONFIGURED`, `CONFIGURATION_INCOMPLETE`, `CONFIGURED`.
- `connectionStatus`: `NOT_CONFIGURED`, `CONFIGURATION_INCOMPLETE`, `NOT_TESTED`, `CONNECTION_SUCCESSFUL`, `AUTHENTICATION_FAILED`, `PROVIDER_UNAVAILABLE`, `UNSUPPORTED_CONFIGURATION`, `TEST_FAILED`. `NOT_TESTED` also means "the configuration changed since the last test" (BR-6). `connectionMessage` and `testedAt` are present only when a test result applies.
- `actions` says which buttons are valid: `configure` (implemented), `test` (configured), `activate` (configured and not active), `deactivate` (active), `setDefault` (active and not default).
- `currencies` are the currencies the provider can take (Razorpay: every currency EIS supports, USD, EUR, GBP and INR); `enabledMethods` is the subset switched on (BR-15). Enum fields are returned as the strings shown.

`Summary`: `{ "registered": 5, "implemented": 1, "configured": 1, "active": 1, "needsConfiguration": 0 }` (`needsConfiguration` counts implemented providers that are not fully configured).

`Detail` (`GET /gateways/{code}` and the result of configure, activate, deactivate and methods):
```json
{
  "gateway": { "…": "a Gateway, as above" },
  "transactionTypes": ["INVOICE_PAYMENT"],
  "environments": ["TEST", "LIVE"],
  "webhookSupport": true,
  "refundSupport": true,
  "recurringSupport": false,
  "fields": [
    { "key": "keyId", "label": "Key ID", "secret": false, "required": true, "webhook": false,

      "configured": true, "source": "ENVIRONMENT", "maskedValue": "rzp_test_••••••7890" },

      "help": "Shown once in the Razorpay Dashboard when the key is created.",
      "configured": true, "source": "STORED", "maskedValue": null },

      "help": "The secret you enter when you add the webhook in the Razorpay Dashboard.",
      "configured": false, "source": "NONE", "maskedValue": null }
  ],
  "setupSteps": ["In the Razorpay Dashboard, create a Test key (or a Live key when you go live).", "…"],
  "webhook": {
    "url": "https://eis.evyoog.com/api/webhooks/razorpay",
    "supported": true,
    "secretConfigured": false,
    "signatureStatus": "NOT_SEEN",
    "lastEventAt": null, "lastEventType": null,
    "failureCount": 2, "lastFailureAt": "2026-10-14T08:00:00Z", "lastFailureReason": "The webhook signature did not verify.",
    "events": ["payment.captured", "payment.failed", "refund.processed"],
    "reachableFromInternet": true
  },
  "evidence": { "authenticated": true, "webhookReceived": false, "paymentCaptured": true, "refundMade": false },
  "configVersion": 3,
  "credentialsUpdatedAt": "2026-10-14T09:10:00Z",
  "encryptionAvailable": true,
  "credentialsUnreadable": false,
  "recentEvents": [ { "eventType": "payment.captured", "receivedAt": "2026-10-14T09:20:00Z", "processedAt": "2026-10-14T09:20:00Z", "paymentId": 17 } ],
  "history": [ { "at": "2026-10-14T09:10:00Z", "action": "PAYMENT_GATEWAY_CONFIGURED", "actor": "keycloak-sub", "detail": "Configuration saved (changed: keySecret)" } ]

```
- `fields` are the provider's configuration fields in order. `source` is `STORED` (saved on the screen), `ENVIRONMENT` (environment or secrets file) or `NONE`. `maskedValue` is **always null for a secret field**, and null when not set. `webhook: true` marks the field the adapter uses to verify webhooks.
- `webhook.url` is `app.backend-url` (environment variable `BACKEND_URL`) + `/webhooks/{code in lower case}`. `signatureStatus`: `VERIFIED` (a correctly signed event was accepted), `NOT_SEEN`, `NOT_APPLICABLE`. `reachableFromInternet` is false when the host is `localhost`, a loopback or `.local` address. `failureCount` counts rejected deliveries since the row was created (BR-13).
- `evidence` comes from real records, not from the connection test (BR-16). `recentEvents` is the last 20 events of this provider (the screen shows 8); `history` the last 10 administrator changes (BR-19), newest first.
- `encryptionAvailable` is false when the master key is not set (BR-3); `credentialsUnreadable` is true when ciphertext is stored that the current key cannot read.
- For a planned provider `fields` list what it will need, `setupSteps` and `webhook.events` are empty, `webhook.supported` still follows the registry entry, and `webhook.url` is the address the endpoint will have (it answers 404 until an adapter exists).

`Connection` (`POST /gateways/{code}/test`): `{ "status": "AUTHENTICATION_FAILED", "message": "Razorpay refused the credentials (HTTP 401).", "testedAt": "2026-10-14T09:15:00Z", "successful": false }`. For `NOT_CONFIGURED` and `CONFIGURATION_INCOMPLETE` the provider is not called, nothing is stored and no audit entry is written.

`SaveConfiguration` (`PUT …/configuration`): `{ "environment": "TEST", "fields": { "keyId": "rzp_test_…", "keySecret": "…" } }`. `environment` (TEST or LIVE, case-insensitive; omitted or blank keeps the current one) and `fields` (field key → value; blank values are ignored and keep the stored value). Each value is trimmed, at most 500 characters, no control characters. Every successful save increases `configVersion`.

`SetMethods` (`PUT …/methods`): `{ "methods": ["card", "upi"] }` (case-insensitive; duplicates ignored). `SetDefault` (`PUT /gateways/default` and `/gateways/active`): `{ "code": "RAZORPAY" }`.

## Errors (gateway endpoints)
| Status | Code | When |
|---|---|---|
| 400 | (validation) | Unknown field key ("Unknown field: …"); a value over 500 characters or with a control character ("{label} is not valid."); an environment the provider does not offer ("Environment must be one of TEST, LIVE."); Razorpay Key ID prefix wrong or not matching the environment (BR-14); methods empty or not supported by the provider |
| 401 | — | No token |
| 403 | — | Signed in without `MANAGE_BILLING` |
| 404 | `NOT_FOUND` | Unknown provider code |
| 409 | `INVALID_STATE` | The provider is **planned** ("The Stripe integration is planned and not available yet." — configure, test, activate, deactivate, methods, default); credentials entered but the server has no encryption key; activate on a gateway that is not fully configured ("… is not fully configured yet."); activate when the connection test fails ("… was not activated: {message}"); a rotation whose test fails ("Not saved: {status}: {message} The previous configuration is unchanged."); default on a gateway that is not active ("Only an active gateway can be the default.") |

## Webhook endpoint
| Method | Path | Authentication | Purpose |
|---|---|---|---|
| POST | `/webhooks/{provider}` | None. The provider's signature header, verified by that provider's adapter against the **raw body** | Receive the provider's payment and refund events |

- `{provider}` is the provider code in any case. Today only `/webhooks/razorpay` exists (the URL is unchanged from [REQ-BIL-001](../../02-requirements/FRD/billing-payments/requirement.md)): header `X-Razorpay-Signature`, events `payment.captured`, `payment.failed`, `refund.processed`.
- **200**, empty body: the event was accepted and processed, or was a repeat of an event already processed for that provider (acknowledged so the provider stops retrying), or an event type nobody subscribed to (recorded and ignored).
- **400 `SIGNATURE_INVALID`**: the signature is missing or does not verify, the provider is not fully configured, or the body cannot be understood. Nothing is changed; one failure is counted on the gateway (BR-13).
- **404**: the provider is unknown or only planned (not counted).
- Idempotent **per provider and event id** (unique on `payment_webhook_event(provider, provider_event_id)`, V038). Accepted for a configured provider even if it is deactivated (BR-13).
- Setting it up per provider: [09-integrations/payment-gateways.md](../../09-integrations/payment-gateways.md#registering-the-webhook-per-provider).

## Changes to the customer payment endpoints
| Endpoint | Change |
|---|---|
| `POST /me/billing/invoices/{invoiceId}/payments` and the organization twin | The backend **routes** the payment (BR-10), using the optional body `method` (`card`, `upi`, `netbanking`, `wallet`). **No eligible gateway: 503 `PAYMENT_GATEWAY_NOT_CONFIGURED`**, message "No payment gateway is available for {currency} {method} payments."; nothing is created. The response gains **`provider`** (the code of the gateway chosen) and **`clientConfig`** (a string map of everything public the browser needs to open that provider's window; never a secret). `keyId` is kept (Razorpay Checkout's public key) and equals `clientConfig.keyId`. |
| `POST /me/billing/payments/{paymentId}/confirm` | Request unchanged. The result is verified by **the payment's own provider** (BR-11); 503 if that provider's credentials are no longer complete. |
| `POST /admin/billing/payments/{paymentId}/refunds` and `/reconcile` | Request unchanged; sent to the payment's own provider. |
| `GET /me/billing/checkout` | `gatewayConfigured` is true when some gateway can take the invoice's currency; `gatewayCode` and `gatewayName` name the gateway that would be used first (default first); the offered methods are those Billing settings allow and an eligible gateway offers (BR-15). |

## Audit actions
`PAYMENT_GATEWAY_CONFIGURED`, `PAYMENT_GATEWAY_CONFIGURATION_REJECTED`, `PAYMENT_GATEWAY_TESTED`, `PAYMENT_GATEWAY_ACTIVATED`, `PAYMENT_GATEWAY_DEACTIVATED`, `PAYMENT_GATEWAY_DEFAULT_CHANGED`, `PAYMENT_GATEWAY_METHODS_CHANGED` — target type `PaymentGateway`, target id the provider code; the detail never contains a credential value (BR-19).
