# API requirements — Entitlements (module `registration`)

Requirement: [REQ-SUB-002](../../02-requirements/FRD/entitlements/requirement.md) (Approved, [C97](../../01-business/roadmap/open-decisions.md#c97) EN-1 to EN-5). Standard REST verbs ([C14](../../01-business/roadmap/open-decisions.md#c14)). The OpenAPI contract is generated by springdoc; `EntitlementController`, `InternalEntitlementController` and the DTOs below are the source of truth.

Entitlements are **read-only and derived** at request time from an ACTIVE subscription, its plan's `includedFeatures` and `usageLimit`, and (for an organization member) the member's product access. There is no write endpoint: nothing can be granted, revoked or edited, and there are no licence keys.

## Customer-facing endpoints
Any signed-in customer. The caller is taken from the token; no customer id is accepted.

| Method | Path | Purpose |
|---|---|---|
| GET | `/me/entitlements` | The signed-in customer's own entitlements: their own ACTIVE individual subscriptions, plus, when they are an ACTIVE member of an organization, the organization's ACTIVE subscriptions to products the member has ACTIVE access to |
| GET | `/organization/me/entitlements` | The caller's organization's entitlements: all its ACTIVE subscriptions (404 if the caller is not an ACTIVE member of an organization). **As built, any ACTIVE member of the organization may call it; no separate organization permission is checked** (see the note in [REQ-SUB-002](../../02-requirements/FRD/entitlements/requirement.md#defaults-applied-not-asked)) |

Response: a JSON array of `EntitlementDto`, empty when nothing is active.

```json
[
  {
    "subscriptionId": 42,
    "productId": 3,
    "productName": "Valam.ai",
    "ownerType": "INDIVIDUAL",
    "planId": 7,
    "planName": "Pro",
    "status": "ACTIVE",
    "expiresAt": "2026-11-02T18:29:00Z",
    "includedFeatures": ["Reports", "API access", "Exports"],
    "usageLimit": 1000,
    "quantity": 1,
    "accessMode": "FULL",
    "graceEndsAt": null
  }
]
```
| Field | Notes |
|---|---|
| `ownerType` | `INDIVIDUAL` or `ORGANIZATION` |
| `includedFeatures` | The plan's comma-separated `includedFeatures`, split and trimmed; empty list when none |
| `usageLimit` | The plan's limit only ([C97](../../01-business/roadmap/open-decisions.md#c97) EN-5); `null` = no limit set. No consumption is ever returned |
| `quantity` | Seats on the subscription (1 for an individual) |
| `accessMode` | `FULL`, or `READ_ONLY` while the subscription's term has ended with auto-renew off and its 7-day grace period runs ([C100](../../01-business/roadmap/open-decisions.md#c100) RR-1 B, [REQ-SUB-002.10](../../02-requirements/FRD/entitlements/requirement.md)) |
| `graceEndsAt` | The end of the grace period while `accessMode` is `READ_ONLY`; otherwise `null` |

## Admin endpoints (platform permission `VIEW_ENTITLEMENTS`)
New support permission **View entitlements** ([C97](../../01-business/roadmap/open-decisions.md#c97) EN-3), enforced for every path under `/admin/entitlements/**` and granted to platform administrators by `RbacSeeder`. Read-only. Each successful lookup is audited as `ENTITLEMENTS_VIEWED` (administrator, target type and id, organization id for an organization).

| Method | Path | Purpose |
|---|---|---|
| GET | `/admin/entitlements/customers/{customerId}` | A customer's entitlements, as the customer would see them (own subscriptions plus organization products they can access) |
| GET | `/admin/entitlements/organizations/{organizationId}` | An organization's entitlements |

> Earlier drafts named the customer lookup `/admin/customers/{id}/entitlements`. The path built, and documented here, is `/admin/entitlements/customers/{id}`.

## Internal endpoint (hosted products)
Backend-to-backend, no user token. Authentication is the `X-Internal-Sso-Secret` header, compared in constant time with the same shared secret as the internal SSO bridge (`INTERNAL_SSO_SHARED_SECRET`, property `vyoog.internal.sso-shared-secret`). A missing, wrong or unset secret is **403**. EIS proposes this contract and the product teams adopt it ([C97](../../01-business/roadmap/open-decisions.md#c97) EN-2).

| Method | Path | Authentication | Purpose |
|---|---|---|---|
| POST | `/internal/entitlements/check` | `X-Internal-Sso-Secret` | Is this product (and optionally this feature) available to this customer or organization? |

Request:
```json
{ "customerId": 12, "organizationId": null, "productId": 3, "featureKey": "API access" }
```
| Field | Required | Notes |
|---|---|---|
| `customerId` | One of the two | An individual customer, or an organization member |
| `organizationId` | One of the two | The organization as a whole. With `customerId` as well: that customer as a member of that organization |
| `productId` | Yes | A body without it is **400** |
| `featureKey` | No | Matched case-insensitively against the plan's `includedFeatures` |

Response (always **200** for a normal answer, allowed or not):
```json
{
  "allowed": true,
  "reason": null,
  "productId": 3,
  "plan": "Pro",
  "ownerType": "INDIVIDUAL",
  "expiresAt": "2026-11-02T18:29:00Z",
  "includedFeatures": ["Reports", "API access", "Exports"],
  "usageLimit": 1000,
  "accessMode": "FULL",
  "graceEndsAt": null
}
```
| `reason` (when `allowed` is false) | Meaning |
|---|---|
| `NO_SUBSCRIPTION` | No ACTIVE subscription that is still in its term or in its read-only grace period (SUSPENDED, CANCELLED, EXPIRED and PENDING_SUBSCRIPTION grant nothing) |
| `NO_MEMBER_ACCESS` | The organization has an ACTIVE subscription, but the named member is not an ACTIVE member or has no ACTIVE access to that product |
| `FEATURE_NOT_INCLUDED` | The subscription is active but the plan does not list `featureKey`; `plan`, `includedFeatures` and `usageLimit` are still returned |
| `UNKNOWN_PRODUCT` | `productId` is not an ACTIVE catalogue product |
| `BAD_REQUEST` | Neither `customerId` nor `organizationId` was given |

For every `NO_SUBSCRIPTION`, `NO_MEMBER_ACCESS`, `UNKNOWN_PRODUCT` and `BAD_REQUEST` answer, `plan`, `ownerType`, `expiresAt`, `usageLimit`, `accessMode` and `graceEndsAt` are `null` and `includedFeatures` is `[]`. A `FEATURE_NOT_INCLUDED` answer still returns `accessMode` and `graceEndsAt`. The hosted product enforces the returned `usageLimit` itself ([C97](../../01-business/roadmap/open-decisions.md#c97) EN-5).

### Read-only during the grace period
[C100](../../01-business/roadmap/open-decisions.md#c100) RR-1 B. When a term has ended with auto-renew off, the subscription stays ACTIVE for **7 days** (a grace period). The check then answers **`allowed: true`** with **`accessMode: "READ_ONLY"`** and **`graceEndsAt`**; the hosted product must **not allow changes** (create, edit, delete) and should tell the customer that renewing restores full access. Renewing, or turning auto-renew back on, makes the next answer `FULL`; when the grace period ends the answer is `NO_SUBSCRIPTION`. The mode starts when the hourly expiry job sets the grace end date, so for up to an hour after the term end the answer is still `NO_SUBSCRIPTION`. Do not cache the answer for long.

```json
{ "allowed": true, "reason": null, "productId": 3, "plan": "Pro", "ownerType": "INDIVIDUAL",
  "expiresAt": "2026-11-02T18:29:00Z", "includedFeatures": ["Reports"], "usageLimit": 1000,
  "accessMode": "READ_ONLY", "graceEndsAt": "2026-11-09T18:29:00Z" }
```

### How a hosted product adopts it
1. Store `INTERNAL_SSO_SHARED_SECRET` in the product's backend environment (never in the frontend).
2. Before serving a feature, call the check with the customer (and organization, when the user acts for one) and the EIS `productId`. Cache the answer briefly at most; a plan change shows at once.
3. Treat `allowed: false` as "do not serve" and show a message based on `reason`; treat `accessMode: READ_ONLY` as "serve, but read-only"; count usage per customer or organization and refuse beyond `usageLimit`.

## Errors
| Status | Code | When |
|---|---|---|
| 400 | `VALIDATION_ERROR` | Internal check without `productId` |
| 401 | — | Customer-facing and admin endpoints without a token |
| 403 | — | Internal check: missing or wrong `X-Internal-Sso-Secret`. Admin endpoints: caller lacks `VIEW_ENTITLEMENTS` |
| 404 | `NOT_FOUND` | Admin lookup of an unknown customer or organization ("Customer not found" / "Organization not found"); `/organization/me/entitlements` for a caller with no organization |
