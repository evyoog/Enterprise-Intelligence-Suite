# BR-MED-001 — Private media storage

**Status:** Draft (2026-10-05, [C72](../01-business/roadmap/open-decisions.md#c72)). Used by REQ-KNW-003 and REQ-KNW-004.

1. Knowledge files live in a **private** S3 bucket: Block Public Access on, bucket owner enforced; objects are never made public.
2. Uploads go **browser → S3** with a short-lived presigned PUT URL; downloads and playback go **S3 → browser** with a short-lived presigned GET URL issued only after authentication and authorization (BR-KVS-001). Large files never pass through the backend.
3. AWS credentials and signing material never reach React, the browser, HTML, JavaScript, local/session storage, any API response or any log. Credentials: an IAM role where available, otherwise keys only in `config/secrets.env` (BR-SEC-001).
4. Object keys are generated by the backend (`{prefix}/{product}/{module}/{uuid}.{ext}`); the original file name is stored as metadata only.
5. The backend verifies every completed upload (object exists, size and content type match) before the record becomes usable.
6. No permanent S3 URL is stored in content or returned to clients.
