# Acceptance criteria — Organization MFA Policy

Each criterion maps to at least one test case in `test-cases/functional/<feature>/` once the FRD is Approved.

| ID | Criterion | Test cases |
|---|---|---|
| AC-1 | **Given** a caller with `MANAGE_ORGANIZATION` **When** they turn the MFA requirement on **Then** `GET /organization/me` returns `mfaRequired: true` and an `MFA_POLICY_CHANGED` audit record exists | [TC-IAM-001](../../../../test-cases/functional/organization-mfa-policy/TC-IAM-001.md) |
| AC-2 | **Given** a caller with `MANAGE_ORGANIZATION` **When** they turn the MFA requirement off **Then** `GET /organization/me` returns `mfaRequired: false` | [TC-IAM-002](../../../../test-cases/functional/organization-mfa-policy/TC-IAM-002.md) |
| AC-3 | **Given** an organization member without `MANAGE_ORGANIZATION` **When** they call `PATCH /organization/me/mfa-policy` **Then** the response is 403 "You do not have permission to do this" and the UI shows that message | [TC-IAM-003](../../../../test-cases/functional/organization-mfa-policy/TC-IAM-003.md) |
| AC-4 | **Given** an organization that requires MFA **When** a member with no authenticator signs in with a password and no one-time password **Then** no session is issued and the sign-in continues to authenticator set-up (changed 2026-09-26, C29) | [TC-IAM-004](../../../../test-cases/functional/organization-mfa-policy/TC-IAM-004.md) |
| AC-5 | **Given** members are signed in **When** the requirement is turned on **Then** no existing session is ended | [TC-IAM-005](../../../../test-cases/functional/organization-mfa-policy/TC-IAM-005.md) |
| AC-6 | **Given** the MFA setting is shown **Then** its text exists in `en.json` and `es.json`, it is keyboard operable, and a jest-axe check reports no violations | [TC-IAM-006](../../../../test-cases/functional/organization-mfa-policy/TC-IAM-006.md) |
| AC-7 | **Given** an organization that requires MFA and a SAML identity provider **When** a member with no authenticator signs in through SAML **Then** no session cookie is set, the browser goes to `/?mfaEnroll=<id>`, and the session is issued only after a valid first code; the recovery codes are shown once | [TC-IAM-045](../../../../test-cases/functional/organization-mfa-policy/TC-IAM-045.md) |
| AC-8 | **Given** a member who already set up an authenticator **When** they sign in through SAML or with a password **Then** the sign-in waits for their code (`/?mfaChallenge=<id>` after SAML) before a session is issued | [TC-IAM-046](../../../../test-cases/functional/organization-mfa-policy/TC-IAM-046.md) |
| AC-9 | **Given** a held sign-in **When** a wrong code is entered, or an ENROLL challenge is used as a VERIFY challenge **Then** it is refused, the attempt is counted, and no session is issued | [TC-IAM-047](../../../../test-cases/functional/organization-mfa-policy/TC-IAM-047.md) |
| AC-10 | **Given** an organization that does not require MFA **When** a member with no authenticator signs in through SAML **Then** the session is issued straight away, as before | [TC-IAM-048](../../../../test-cases/functional/organization-mfa-policy/TC-IAM-048.md) |
| AC-11 | **Given** the set-up step in the sign-in dialog **When** it is shown **Then** its text exists in `en.json` and `es.json`, it is keyboard operable, and a jest-axe check reports no violations | [TC-IAM-049](../../../../test-cases/functional/organization-mfa-policy/TC-IAM-049.md) |
