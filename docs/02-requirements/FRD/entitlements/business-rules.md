# Business rules — Entitlements (REQ-SUB-002)

| ID | Rule |
|---|---|
| BR-1 | An entitlement exists only while its subscription's status is ACTIVE **and its term has not ended, or it is in its read-only grace period (BR-11)**. SUSPENDED, CANCELLED and EXPIRED subscriptions grant nothing, with no separate action needed to "revoke" them — ending the subscription already ends the entitlement ([C52](../../../01-business/roadmap/open-decisions.md#c52)). |
| BR-2 | Included features and usage limits shown are exactly the values on the subscription's current plan — never cached or copied elsewhere, so a plan change takes effect immediately. |
| BR-3 | A usage limit is shown as a value only; nothing in this feature tracks or enforces consumption against it. EIS stores **only the limit** from the plan; each hosted product counts its own usage and enforces the limit ([C97](../../../01-business/roadmap/open-decisions.md#c97) EN-5). |
| BR-4 | A customer sees only their own subscriptions' entitlements (the customer endpoint takes no customer id — it always answers for the signed-in caller, so another customer's entitlements cannot be requested through it). The platform administrator lookup is the only way to see someone else's (BR-7). |
| BR-5 | The internal entitlements check (`POST /internal/entitlements/check`) is reachable only with a valid `X-Internal-Sso-Secret` header; missing or wrong secret is refused with 403, the same convention as the existing internal SSO bridge (`InternalSsoController`). |
| BR-6 | **Entitlements are read-only and derived** ([C97](../../../01-business/roadmap/open-decisions.md#c97) EN-1). They come from the ACTIVE subscription, the plan's included features and, for an organization member, the member's product access. Nothing is granted, revoked, stored or edited; no entitlement table exists. |
| BR-7 | **Administrator lookup** ([C97](../../../01-business/roadmap/open-decisions.md#c97) EN-3): a platform administrator holding `VIEW_ENTITLEMENTS` ("View entitlements") may look up any customer's or organization's entitlements. It is read-only, an unknown customer or organization is a 404, and every lookup is written to the audit log as `ENTITLEMENTS_VIEWED` with the administrator, the target and the time. Without the permission: 403. |
| BR-8 | **Organization members** ([C97](../../../01-business/roadmap/open-decisions.md#c97) EN-1): an organization member gets an organization subscription's entitlement only when the member's own access to that product is ACTIVE. The organization as a whole (no member named) gets the entitlement of every ACTIVE organization subscription. |
| BR-9 | **No licence keys** ([C97](../../../01-business/roadmap/open-decisions.md#c97) EN-4): nothing in EIS issues, validates or revokes a licence key. Access is decided only by BR-1, BR-2 and BR-8. |
| BR-10 | **Internal check answers** ([C97](../../../01-business/roadmap/open-decisions.md#c97) EN-2): a normal "no" is never an error. The answer is HTTP 200 with `allowed: false` and one reason: `NO_SUBSCRIPTION` (no ACTIVE, in-term subscription), `NO_MEMBER_ACCESS` (the organization has one but the member lacks product access), `FEATURE_NOT_INCLUDED` (the plan does not list the feature key; the plan, limit and features are still returned), `UNKNOWN_PRODUCT` (not an ACTIVE catalogue product), `BAD_REQUEST` (neither `customerId` nor `organizationId`). A malformed body (no `productId`) is HTTP 400. |
| BR-11 | **Read-only grace period** ([C100](../../../01-business/roadmap/open-decisions.md#c100) RR-1 B, [REQ-SUB-004.13 to .15](../renewal-reminders/requirement.md)). A subscription that is ACTIVE, whose term end has passed and whose grace end date (`graceEndsAt`, set by the hourly expiry job to the term end + 7 days) is in the future grants an entitlement with `accessMode = READ_ONLY` and `graceEndsAt` set. In every other allowed case `accessMode` is `FULL` and `graceEndsAt` is null. Once the grace end date passes, or after renewal clears it, the usual rules apply (BR-1). EIS reports the mode; the hosted product enforces it. For an organization member the member's own product access still applies first (BR-8). |
