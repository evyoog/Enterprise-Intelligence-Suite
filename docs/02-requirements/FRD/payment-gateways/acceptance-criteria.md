## The product owner's 17 acceptance points
The acceptance points of [C98](../../../01-business/roadmap/open-decisions.md#c98) map to the criteria above:

| # | Point | Criteria |
|---|---|---|
| 1 | The page shows the registered providers | AC-1, AC-31, AC-32 |
| 2 | The page is not Razorpay-only | AC-2, AC-30 |
| 3 | Each gateway is configured independently | AC-4, AC-8 |
| 4 | Credentials and webhook configuration are separate per gateway | AC-5, AC-28 |
| 5 | Credentials are masked | AC-6, AC-7, AC-26, AC-29, AC-36 |
| 6 | Connection tests are real | AC-9, AC-27, AC-33 |
| 7 | Activation is blocked while configuration is incomplete | AC-10, AC-13, AC-22 |
| 8 | Several gateways can be active at once | AC-11 |
| 9 | A default gateway can be selected | AC-8, AC-12 |
| 10 | The backend routes each payment | AC-14, AC-15, AC-16, AC-21, AC-30 |
| 11 | Webhooks are signature-verified | AC-17, AC-19, AC-34 |
| 12 | No duplicate financial operations | AC-18, AC-34 |
| 13 | The existing Razorpay flow still works | AC-16, AC-23, AC-35 |
| 14 | New providers need no UI rewrite | AC-2, AC-29 |
| 15 | Unsupported providers are never operational | AC-3 |
| 16 | Provider failures do not create wrong statuses | AC-10, AC-13, AC-20, AC-24 |
| 17 | Existing routes and permissions stay compatible | AC-23, AC-25 |

AC-33 to AC-35 are manual-only (a real Razorpay connection, a real webhook delivery, the migration on a real database) and are **Not Run**: they need real Razorpay keys, a public backend URL and a PostgreSQL copy of the schema.
