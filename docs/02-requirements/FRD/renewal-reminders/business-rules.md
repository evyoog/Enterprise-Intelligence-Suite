# Business rules — Auto-renewal and renewal reminders (REQ-SUB-004)

| ID | Rule | Enforced in | Source |
|---|---|---|---|
| BR-1 | A new subscription on a Monthly or Yearly plan gets auto-renew ON and a renewal date one billing period after its start. | backend | .1 |
| BR-2 | At or after its renewal date, an ACTIVE subscription with auto-renew ON is renewed: a scheduled plan downgrade and a scheduled seat decrease are applied, the term is extended by one period from the old renewal date, any grace end date is cleared, a renewal invoice is generated (non-zero price; organization: price × seats), `SubscriptionRenewed` is published and the owner is notified. A subscription is renewed once per term (the renewal date moves forward). | backend | .2 |
| BR-3 | Automatic charging is used only when `canChargeAutomatically` is true — never today (no reusable Razorpay token). | backend | .2 |
| BR-4 | Effective settings per recipient: enabled (user, default on); days before = user value, else platform default (default 7); send time = user value, else platform default (default 09:00); time zone = user preference `timeZone`, else platform default time zone. | backend | .4, .5, .7, .8 |
| BR-5 | A reminder is due for (subscription, recipient) when the subscription is ACTIVE, reminders are enabled, and in the recipient's time zone: 1 ≤ (renewal date − today) ≤ days before, and the local time ≥ send time. Auto-renew on or off makes no difference. | backend | .6, .7 |
| BR-6 | At most one reminder per subscription, recipient and local date, **before or after the term end**: the log row (unique) is written before the notification; a second attempt the same day finds it and sends nothing. | database + backend | .7, .16 |
| BR-7 | Days before: 1–30 (user and platform). Send time: `HH:mm` 24-hour. Time zone: a valid IANA name. | backend | .8 |
| BR-8 | **Recipients** ([C100](../../../01-business/roadmap/open-decisions.md#c100) RR-2 B, RR-5): an individual subscription's owner; for an organization subscription the ACTIVE organization admins, the ACTIVE members who hold `MANAGE_ORGANIZATION_BILLING`, and the people an administrator added who are still ACTIVE members. Each person gets one reminder per day: if a person is both a default recipient and added, the default (both channels) applies. *Supersedes "the ACTIVE organization admins".* | backend | .18 |
| BR-9 | Reminders off does not change auto-renew or renewal. | backend | .10 |
| BR-10 | Audit: `RENEWAL_REMINDER_SENT`, `RENEWAL_REMINDER_PREFERENCES_CHANGED` (user), `RENEWAL_REMINDER_DEFAULTS_CHANGED` (platform), `SUBSCRIPTION_AUTO_RENEWED`, `SUBSCRIPTION_AUTO_RENEW_CHANGED`, `SUBSCRIPTION_GRACE_STARTED`, `SUBSCRIPTION_EXPIRED`, `RENEWAL_REMINDER_RECIPIENTS_CHANGED`. | backend | .11, .12, .13, .19 |
| BR-11 | **Auto-renew switch** ([C100](../../../01-business/roadmap/open-decisions.md#c100) RR-1 B): allowed only on an ACTIVE or SUSPENDED subscription that has a renewal date (otherwise 400). An individual changes their own; an organization subscription is changed by a user with `MANAGE_ORGANIZATION_BILLING` or `MANAGE_SUBSCRIPTIONS` of the same organization (others 403, another organization's subscription 404). Setting the value it already has changes nothing and writes no audit entry. | backend | .3, .12 |
| BR-12 | **Grace period starts:** the hourly expiry job finds ACTIVE subscriptions with auto-renew OFF whose term end has passed and that have no grace end date. It sets the grace end date to the term end + 7 days and leaves the subscription ACTIVE (read-only); it notifies an individual owner, audits `SUBSCRIPTION_GRACE_STARTED` and publishes `SubscriptionChanged`. If that grace end date is already in the past (the job was down for more than 7 days) the subscription is expired instead. SUSPENDED and CANCELLED subscriptions are never touched. | backend | .13 |
| BR-13 | **Grace period ends:** when the grace end date has passed the job sets the status to EXPIRED, notifies an individual owner, audits `SUBSCRIPTION_EXPIRED` and, for an organization subscription, refreshes the members' product access. An EXPIRED subscription grants nothing. | backend | .13 |
| BR-14 | **Renewing in grace:** renewing (the auto-renew job, an individual's Renew) clears the grace end date; turning auto-renew **on** while the term has ended and a grace end date is set renews at once through the auto-renew rule (BR-2), so the new term runs from the old renewal date. Turning it on before the term ends changes only the flag. | backend | .14 |
| BR-15 | **Grace reminders:** for a subscription whose term has ended and that has a grace end date (status ACTIVE or EXPIRED), a reminder is due for a recipient with reminders enabled when, in the recipient's time zone, the local date is from the day the term ended up to and including the local date of the grace end date, and the local time ≥ send time. The cut-off is therefore the end of the local grace day, not the grace instant. The reminder's `daysBefore` is the (negative or zero) number of days after the term end. A renewed subscription has no grace end date and gets none. | backend | .16 |
| BR-16 | **Recipient list:** `PUT /organization/me/renewal-reminder-recipients` replaces the added people. It needs `MANAGE_ORGANIZATION_BILLING`; every entry must be an ACTIVE member of the caller's organization (400 "Only active members of your organization can be added."), listed once (400 "A person is listed twice."), with email, in-app or both (400 "Choose email, in-app or both for every person you add."); at most 200 entries. An added person who is also a default recipient is not shown as added. | backend | .19 |
| BR-17 | **Channels:** a default recipient gets both channels. An added person gets exactly the chosen channels, for the renewal reminder and the grace reminder alike; a person with both off cannot be saved. | backend | .19, .20 |
| BR-18 | **Wording:** the renewal reminder and the grace reminder are the message templates `NOTIF_RENEWAL_REMINDER` and `NOTIF_RENEWAL_GRACE_REMINDER`, in the recipient's language, with the placeholders the template lists (including `graceEnd` for the grace template). | backend | .17, .20 |
| BR-19 | **Free trials are not candidates.** The reminder job skips every subscription with `trial` = true (`RenewalReminderService#sendDue`), so no renewal reminder is sent for a trial, however close its end date is. The trial's own notice (3 days before the end, once, and at the end) is [BR-EVL-010 and BR-EVL-011](../product-evaluation/business-rules.md). | backend | .21 |
