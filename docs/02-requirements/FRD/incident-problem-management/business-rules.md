# Business rules — Incident and problem management (REQ-SUP-003)

Decided in [C101](../../../01-business/roadmap/open-decisions.md#c101) (IC-1 A, IC-2 A, 2026-10-14). Enforced by the backend; the cited class and method are the source of truth.

| ID | Rule | Enforced in | Source |
|---|---|---|---|
| BR-INC-001 | **One record.** A support incident is a `service_incident` row, the same one the status page shows. Creating an incident (`POST /admin/service-status/incidents`) is posting it on the status page; there is no second incident table. | backend, database | .1; `IncidentManagementService` |
| BR-INC-002 | **Public fields** (title up to 200, message up to 4000, product, start, end) are returned to customers who purchased the product ([BR-PRT-001.3](../service-status-page/business-rules.md)) as `IncidentDto`. **Internal fields** (severity, phase, internal notes, assignee, resolution summary, closed time, linked tickets, problem) exist only in `AdminIncidentDto`, returned by `/admin/service-status/**`. The customer record has no such component. | backend | .2; `ServiceStatusService#toIncidentDto`, `AdminIncidentDto` |
| BR-INC-003 | **Product.** An incident is for an ACTIVE catalog product (404 "Product not found" otherwise). A new incident is `LOGGED` with severity `MINOR` unless sent. | backend | .1, .4 |
| BR-INC-004 | **Phases and the end time.** `LOGGED` and `INVESTIGATING` have no end time: an end time sent with them is refused (400 "An incident that is logged or investigating has no end time. Mark it resolved instead."). **`RESOLVED`** needs a resolution summary (400 "Write a resolution summary before marking the incident resolved.") and sets the end time to the one sent, else the one it had, else now. **`CLOSED`** is allowed only from `RESOLVED` (400 "Only a resolved incident can be closed."), keeps the end time, and stores the closing time. | backend | .3; `IncidentManagementService#apply` |
| BR-INC-005 | **Phase left out.** When no phase is sent, an end time means `RESOLVED`; no end time on a `RESOLVED` incident means it is reopened as `INVESTIGATING`; otherwise the phase is unchanged. | backend | .3 |
| BR-INC-006 | **Closed is final.** A closed incident cannot be updated and its tickets cannot be linked or unlinked (400 "A closed incident cannot be changed."). | backend | .3, .6 |
| BR-INC-007 | **End after start.** An end time before the start time is refused (400 "The end time must be after the start time.") whichever phase is used. | backend | .3; BR-PRT-001.5 |
| BR-INC-008 | **Internal fields on update.** Severity, internal notes and the assignee left out of an update keep their value; a resolution summary left out keeps its value; a blank internal note clears it. An assignee must be an existing customer (400 "The assignee does not exist."). The public fields are replaced by what the update sends. | backend | .4, .5 |
| BR-INC-009 | **Linked tickets.** A ticket that exists can be linked to an incident (404 "Ticket not found" otherwise) and unlinked; linking twice changes nothing; the link disappears if the ticket is deleted. The incident shows each ticket's id, subject, status and priority. | backend, database | .6 |
| BR-INC-010 | **Problem** requires a title of 1 to 200 characters (400 "Give the problem a title of up to 200 characters."); description and root cause up to 4000 characters; a new problem is `OPEN`. A problem can be created with a list of incidents to link. | backend | .7; `ProblemService#create` |
| BR-INC-011 | **An incident belongs to at most one problem** (`service_incident.problem_id`). Linking an incident that belongs to another problem is refused (400 "Incident {id} already belongs to problem {id}."); linking it to the same problem again changes nothing; an unknown incident is 404 "Incident not found". Unlinking sets `problem_id` to null; unlinking an incident that is not in this problem changes nothing. A closed problem takes no links and no unlinking. If a problem is deleted its incidents are freed (`ON DELETE SET NULL`); there is no delete endpoint. | backend, database | .8; `ProblemService#link`, `#unlinkIncident` |
| BR-INC-012 | **Problem statuses.** `ROOT_CAUSE_IDENTIFIED` needs a root cause (400 "Write the root cause first."). `RESOLVED` needs a root cause (400 "A problem needs a root cause before it can be resolved."), may be reached from `OPEN`, and stores the resolved time. `CLOSED` only from `RESOLVED` (400 "Only a resolved problem can be closed.") and only when no corrective action is open (400 "Finish every corrective action first ({n} still open)."); it stores the closing time. Moving back to `OPEN` or `ROOT_CAUSE_IDENTIFIED` clears the resolved time. A root cause sent in the same request counts. | backend | .9; `ProblemService#moveTo` |
| BR-INC-013 | **Closed is final.** A closed problem cannot be updated, and no incident or action can be added, changed, removed or deleted (400 "A closed problem cannot be changed."). | backend | .9, .10 |
| BR-INC-014 | **Corrective actions.** Description required, up to 500 characters (400 "Describe the action in up to 500 characters."); owner up to 100 characters (free text); due date optional; `done` false by default. Marking an action done stores the time, marking it open clears it. Actions can be added, updated (fields left out keep their value) and deleted. An action of another problem is 404 "Action not found". | backend | .10 |
| BR-INC-015 | **Counts.** A problem in the list shows its number of incidents, of actions and of open actions. | backend | .8, .10 |
| BR-INC-016 | **Permission.** All incident and problem endpoints are under `/admin/service-status/**`: platform permission `MANAGE_SERVICE_STATUS` (seeded for `ADMIN`); 401 without a token, 403 without the permission. Customers have no endpoint to the internal fields. | `SecurityConfig` | .11 |
| BR-INC-017 | **Audit.** `INCIDENT_POSTED`, `INCIDENT_UPDATED` (with the phase change), `INCIDENT_TICKET_LINKED`, `INCIDENT_TICKET_UNLINKED`, `PROBLEM_CREATED`, `PROBLEM_UPDATED`, `PROBLEM_INCIDENT_LINKED`, `PROBLEM_INCIDENT_UNLINKED`, `PROBLEM_ACTION_ADDED`, `PROBLEM_ACTION_UPDATED`, `PROBLEM_ACTION_DELETED`. The earlier status-page entry `SERVICE_STATUS_CHANGED` is unchanged. | backend | .12 |
| BR-INC-018 | **Existing incidents.** The migration gives incidents already ended phase `RESOLVED` and the others `INVESTIGATING`, with severity `MINOR`; new incidents default to `LOGGED` in the application. | database | .13 |
| BR-INC-019 | **Business dashboard.** The organization business dashboard's service-status alert still counts incidents without an end time ([BR-PRT-001.6](../service-status-page/business-rules.md)); phases do not change it. | backend | .1 |

Rules shared with other features belong in `docs/03-business-rules/` and are referenced here by ID.
