# Acceptance criteria — Incident and problem management (REQ-SUP-003)

Each criterion maps to at least one test case in `test-cases/functional/incident-problem-management/` ([TESTPLAN-SUP-003](../../../../test-cases/functional/incident-problem-management/TESTPLAN-SUP-003.md)).

| ID | Requirement | Criterion | Test case |
|---|---|---|---|
| AC-1 | .1, .2, .4, .5 | **Given** an administrator logs an incident with a severity and internal notes **then** it is `LOGGED`, open, has that severity and those notes, and appears in the status page's administrator list; **then** the customer incident record has none of `severity`, `phase`, `internalNotes`, `assignedToCustomerId`, `resolutionSummary`, `problemId`, `tickets`. | [TC-SUP-021](../../../../test-cases/functional/incident-problem-management/TC-SUP-021.md) |
| AC-2 | .3 | **Given** an incident **when** it is moved to Investigating **then** it is Investigating; **when** it is marked Resolved with a blank summary **then** it is refused ("resolution summary"); **when** it is closed before it is resolved **then** it is refused ("resolved"); **when** it is resolved with a summary **then** it has an end time and is no longer open; **when** it is closed **then** its closing time is set; **when** a closed incident is changed **then** it is refused ("closed"). | [TC-SUP-022](../../../../test-cases/functional/incident-problem-management/TC-SUP-022.md) |
| AC-3 | .3 | **Given** an incident being investigated **when** an end time is sent with that phase **then** it is refused. | [TC-SUP-023](../../../../test-cases/functional/incident-problem-management/TC-SUP-023.md) |
| AC-4 | .3 | **Given** a resolved incident **when** its end time is removed **then** it becomes Investigating and open again. | [TC-SUP-024](../../../../test-cases/functional/incident-problem-management/TC-SUP-024.md) |
| AC-5 | .5, .6 | **Given** an incident with an assignee **then** the assignee's name is shown; **when** a ticket is linked **then** it is listed with its subject, status and priority; linking it twice changes nothing; unlinking removes it; an unknown ticket is refused (404) and an unknown assignee is refused. | [TC-SUP-025](../../../../test-cases/functional/incident-problem-management/TC-SUP-025.md) |
| AC-6 | .7, .8 | **Given** two incidents **when** a problem is created with them **then** both are linked and show the problem's title; **when** another problem tries to link one of them **then** it is refused ("already belongs"); **when** one is unlinked **then** it is free to join another problem. | [TC-SUP-026](../../../../test-cases/functional/incident-problem-management/TC-SUP-026.md) |
| AC-7 | .9, .10 | **Given** a new problem **when** it is resolved without a root cause **then** it is refused ("root cause"); **when** it is closed before it is resolved **then** it is refused; **when** the root cause is written and the status set to Root cause identified **then** it changes; **given** an open corrective action **when** the problem is resolved **then** it is Resolved with a resolved time; **when** it is closed **then** it is refused ("corrective action") until the action is marked done (done time set); then it closes with a closing time; **then** a closed problem takes no title change and no new action. | [TC-SUP-027](../../../../test-cases/functional/incident-problem-management/TC-SUP-027.md) |
| AC-8 | .8, .9 | **Given** a closed problem **when** an incident is linked **then** it is refused; **when** a problem is created with a blank title **then** it is refused; **when** an unknown problem is read **then** 404. | [TC-SUP-028](../../../../test-cases/functional/incident-problem-management/TC-SUP-028.md) |
| AC-9 | .8, .10 | **Given** a problem with one incident and two actions, one done, **then** the list shows 1 incident, 2 actions and 1 open action. | [TC-SUP-029](../../../../test-cases/functional/incident-problem-management/TC-SUP-029.md) |
| AC-10 | .2 | **Given** two customers, one who purchased the product **when** each opens the status page **then** only the purchaser sees the incident's title, message and times, and neither receives any internal field. | [TC-SUP-030](../../../../test-cases/functional/incident-problem-management/TC-SUP-030.md) |
| AC-11 | .11 | **Given** a user without `MANAGE_SERVICE_STATUS` **when** calling `/admin/service-status/incidents…` or `/problems…` **then** 403 (401 without a token); **given** an administrator **then** 200. | [TC-SUP-031](../../../../test-cases/functional/incident-problem-management/TC-SUP-031.md) |
| AC-12 | .1, .3, .5, .6 | **Given** the Incidents tab **then** it lists incidents with severity, phase, assignee, tickets and problem, filters by phase, creates and edits an incident (public and internal fields in separate groups, only the allowed phases offered, a resolution summary required to resolve), links and unlinks tickets, and shows a closed incident read-only; it has an empty and an error state and passes the axe test. | [TC-SUP-032](../../../../test-cases/functional/incident-problem-management/TC-SUP-032.md) |
| AC-13 | .7 to .10 | **Given** the Problems tab **then** it lists problems with status, incident count and open actions, creates a problem (optionally with incidents), shows the detail (details, status move, linked incidents, corrective actions), explains why a status move is blocked, and shows a closed problem read-only; it has an empty and an error state and passes the axe test. | [TC-SUP-033](../../../../test-cases/functional/incident-problem-management/TC-SUP-033.md) |
| AC-14 | .1 | **Given** the status page administration (Manage tab) **then** it posts a product's status with a note and **no longer has an incident form**; incidents are managed on the Incidents tab. | [TC-SUP-034](../../../../test-cases/functional/incident-problem-management/TC-SUP-034.md) |
| AC-15 | .12 | **Given** each incident, ticket-link, problem, problem-link and action change **then** the audit entry named in REQ-SUP-003.12 exists. | [TC-SUP-035](../../../../test-cases/functional/incident-problem-management/TC-SUP-035.md) |
| AC-16 | .13 | **Given** a database with incidents before V041 **when** V041 is applied (once or again) **then** ended incidents are `RESOLVED`, the others `INVESTIGATING`, and a fresh schema load gives the same tables. | [TC-SUP-036](../../../../test-cases/functional/incident-problem-management/TC-SUP-036.md) |
