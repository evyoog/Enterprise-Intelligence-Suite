# Business rules — Interim Service Status Page

Decided in [C20](../../../01-business/roadmap/open-decisions.md#c20) (2026-09-25) and [C26](../../../01-business/roadmap/open-decisions.md#c26) (2026-09-26). Enforced by the backend; the cited class and method are the source of truth.

| ID | Rule | Enforced in | Source |
|---|---|---|---|
| BR-PRT-001.1 | Status and incidents are posted **manually** by platform administrators with the platform permission `MANAGE_SERVICE_STATUS` (seeded for `ADMIN`). Otherwise 401/403. | backend | `SecurityConfig` (`/admin/service-status/**`), `RbacSeeder` |
| BR-PRT-001.2 | Status values: Operational, Degraded, Partial outage, Major outage, Maintenance. A product with no posted status is Operational (**from C101**, a product with recently reporting instances shows the status derived from them instead: BR-PRT-001.9). Only ACTIVE catalog products are listed or can be posted (404 "Product not found" otherwise). | backend | `ServiceStatusValue`, `ServiceStatusService#updateProductStatus` |
| BR-PRT-001.3 | Every signed-in customer sees every active product's status. Incident details (title, message, times) are returned only for products the customer has purchased: the organization's ACTIVE subscriptions for an organization member, the customer's own ACTIVE subscriptions for an individual. A caller with no customer account sees status only. | backend | `ServiceStatusService#customerView`, `#purchasedProductIds` |
| BR-PRT-001.4 | The customer view is switched on or off by `app.status-page.enabled` (default on). When off, `GET /me/service-status` returns `enabled: false` with no products or incidents; the admin view keeps working. | backend + frontend | `ServiceStatusService` constructor, `ServiceStatusPage` |
| BR-PRT-001.5 | An incident is open while it has no end time. The end time may not be before the start time: 400 "The end time must be after the start time." The customer view lists the latest 50 incidents of purchased products; the admin view the latest 200. | backend | `ServiceStatusService#apply`, `ServiceIncidentRepository` |
| BR-PRT-001.6 | The business dashboard raises one alert (type `SERVICE_STATUS`) per purchased product that is not Operational or has an open incident; severity `error` for a major outage, `warning` otherwise. | backend | `BusinessDashboardService#serviceStatusAlerts` |
| BR-PRT-001.7 | Every change is audited: `SERVICE_STATUS_CHANGED`, `INCIDENT_POSTED`, `INCIDENT_UPDATED`. | backend | `ServiceStatusService` |
| BR-PRT-001.8 | In sprint 2027.1.1 per-product status switches to Health Monitoring (10.04). In sprint 2027.1.3 incidents switch to Incident & Problem Management (12.04), and the interim page is removed after that sprint. **Done 2026-10-14 ([C101](../../../01-business/roadmap/open-decisions.md#c101)), in sprint 2027.1.2:** per-product status switched to service instances (BR-PRT-001.9) and incidents to REQ-SUP-003 (BR-PRT-001.10). The removal of the interim page is not part of C101 and is unchanged. | plan | [C20](../../../01-business/roadmap/open-decisions.md#c20) |
| BR-PRT-001.9 | **(C101)** Per-product status is **derived from the instances** that reported in the last 5 minutes (`ServiceStatusService#toStatusDto`, `ServiceInstanceService#derivedStatus`): more than half Down = Major outage; at least one Down = Partial outage; at least one Degraded = Degraded; otherwise Operational. With no recently reporting instance the status posted by an administrator is kept (BR-PRT-001.2); a posted **Maintenance** always wins. The status carries `source` (`INSTANCES` or `MANUAL`) and the instance counts. Details: [BR-SRM-010 to BR-SRM-012](../service-instances/business-rules.md). | backend | [C101](../../../01-business/roadmap/open-decisions.md#c101) SR-3 B |
| BR-PRT-001.10 | **(C101)** An incident is the support incident ([BR-INC-001, BR-INC-002](../incident-problem-management/business-rules.md)): the customer view returns only the public fields (`IncidentDto`); the posting and updating endpoints now return the administrator record with the internal fields, and the end-time rule of BR-PRT-001.5 still holds. An incident is open while it has no end time, which is true of Logged and Investigating incidents. | backend | [C101](../../../01-business/roadmap/open-decisions.md#c101) IC-1 A |
