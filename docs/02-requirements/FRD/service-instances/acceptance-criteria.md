# Acceptance criteria — Service instances (REQ-SRM-001)

Each criterion maps to at least one test case in `test-cases/functional/service-instances/` ([TESTPLAN-SRM-001](../../../../test-cases/functional/service-instances/TESTPLAN-SRM-001.md)).

| ID | Requirement | Criterion | Test case |
|---|---|---|---|
| AC-1 | .1 | **Given** a subscription waiting for payment **then** it has no service instance; **when** it becomes ACTIVE **then** one instance exists with status PROVISIONING and health UNKNOWN; **given** an ACTIVE subscription that has no instance **when** the reconcile job runs **then** the instance is created. | [TC-SRM-001](../../../../test-cases/functional/service-instances/TC-SRM-001.md) |
| AC-2 | .2 | **Given** an instance **when** its subscription is suspended **then** the instance is SUSPENDED; **when** it is active again **then** the instance is PROVISIONING (or ACTIVE if it has reported before); **when** the subscription is cancelled **then** the instance is DEPROVISIONED. | [TC-SRM-002](../../../../test-cases/functional/service-instances/TC-SRM-002.md) |
| AC-3 | .3, .4 | **Given** a reporter key of the product **when** the product reports `degraded` with a message and a tenant reference **then** the report is accepted, the instance becomes ACTIVE with health DEGRADED, the tenant reference is stored and the instance shows it was last changed by PRODUCT; **given** a call with one valid and one invalid health value **then** the valid report is accepted, the other is rejected with "Report 2: …" and the answer counts 1 accepted, 1 rejected. | [TC-SRM-003](../../../../test-cases/functional/service-instances/TC-SRM-003.md) |
| AC-4 | .4 | **Given** a platform administrator **when** a reporter key is created **then** the secret (`eisrk_…`) is returned once and its first 12 characters are listed as the prefix; **then** no listing returns the secret or its hash; the screen shows the secret once with a copy button; **when** the key is revoked (after a confirmation) **then** it shows as revoked. | [TC-SRM-004](../../../../test-cases/functional/service-instances/TC-SRM-004.md) |
| AC-5 | .4 | **Given** the open path `POST /product-reports/health` **when** the key is missing, unknown or revoked **then** it is refused with 401 and nothing is stored; **when** a valid key of another product reports an instance **then** that report is rejected and the instance is unchanged. | [TC-SRM-005](../../../../test-cases/functional/service-instances/TC-SRM-005.md) |
| AC-6 | .9 | **Given** four reporting instances of a product **when** all are Healthy **then** the derived status is Operational; one Degraded: Degraded; one Down: Partial outage; two Down (exactly half): Partial outage; three Down: Major outage with 3 down of 4 reporting. | [TC-SRM-006](../../../../test-cases/functional/service-instances/TC-SRM-006.md) |
| AC-7 | .5, .9 | **Given** an instance whose last report is 10 minutes old **then** it is left out, the product keeps the status an administrator set by hand and the status page shows source MANUAL; the instance is shown as "No recent report". | [TC-SRM-007](../../../../test-cases/functional/service-instances/TC-SRM-007.md) |
| AC-8 | .9 | **Given** a product with a Down instance **then** the status page shows Major outage with source INSTANCES and 1 down instance, and the customer page says "Based on 1 reporting instance (1 down, 0 degraded)"; **when** an administrator sets Maintenance **then** the product shows Maintenance (source MANUAL). | [TC-SRM-008](../../../../test-cases/functional/service-instances/TC-SRM-008.md) |
| AC-9 | .6 | **Given** an instance **when** a platform administrator changes it by hand without a note, or without a status or health, **then** it is refused (400); **when** status ACTIVE and health DOWN are set with a note **then** the instance shows ACTIVE, DOWN, last changed by ADMIN with the note, not stale, and the status page uses it. | [TC-SRM-009](../../../../test-cases/functional/service-instances/TC-SRM-009.md) |
| AC-10 | .8 | **Given** two organizations with instances **when** an organization administrator lists instances **then** only their own organization's are returned (no deprovisioned ones); **when** an ordinary member does so **then** it is refused (403); the screen is read-only, shows the access URL as a link and has an empty and an error state. | [TC-SRM-010](../../../../test-cases/functional/service-instances/TC-SRM-010.md) |
| AC-11 | .7 | **Given** instances in several states **when** a platform administrator opens the Instances tab **then** the summary (instances, healthy, degraded, down, no recent report) and the table show them, and the product, status and health filters narrow the table; an empty and an error state are shown. | [TC-SRM-011](../../../../test-cases/functional/service-instances/TC-SRM-011.md) |
| AC-12 | .4, .7, .8 | **Given** a user without `MANAGE_SERVICE_STATUS` **when** calling `/admin/service-status/instances`, `/instances/{id}` (PUT) or `/reporter-keys` **then** 403 (401 without a token); **given** no token **when** calling `/organization/me/service-instances` **then** 401; **given** a member without `MANAGE_ORGANIZATION` **then** 403. | [TC-SRM-012](../../../../test-cases/functional/service-instances/TC-SRM-012.md) |
| AC-13 | .10 | **Given** a hand change, a key creation and a key revocation **then** the audit log has `SERVICE_INSTANCE_CHANGED` (before and after), `SERVICE_REPORTER_KEY_CREATED` and `SERVICE_REPORTER_KEY_REVOKED`, and no secret appears in any of them. | [TC-SRM-013](../../../../test-cases/functional/service-instances/TC-SRM-013.md) |
| AC-14 | .9 | **Given** a product with no instance reporting **when** the status page is opened **then** it behaves as before C101 (the status an administrator posted, Operational when none; incidents only for purchasers). | [TC-SRM-014](../../../../test-cases/functional/service-instances/TC-SRM-014.md) (regression; re-runs [TC-PRT-001](../../../../test-cases/functional/service-status-page/TC-PRT-001.md) to [TC-PRT-007](../../../../test-cases/functional/service-status-page/TC-PRT-007.md)) |
| AC-15 | Accessibility, i18n | **Given** the Instances tab, the reporter-key dialogs and the organization instances screen **then** each passes the axe test and its text exists in `en.json` and `es.json`. | [TC-SRM-011](../../../../test-cases/functional/service-instances/TC-SRM-011.md), [TC-SRM-010](../../../../test-cases/functional/service-instances/TC-SRM-010.md) |
| AC-16 | .11, BR-SRM-016 | **Given** a free trial **when** it starts **then** its instance is PROVISIONING; **when** it ends **then** the instance is DEPROVISIONED (added 2026-10-15, [C102](../../../01-business/roadmap/open-decisions.md#c102)) | [TC-MKT-053](../../../../test-cases/functional/product-evaluation/TC-MKT-053.md), [TC-MKT-056](../../../../test-cases/functional/product-evaluation/TC-MKT-056.md) |
