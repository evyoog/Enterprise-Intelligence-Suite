# Business rules — Privileged Access (User and Organization Administrator)

These rules are **already enforced by the backend**. They are documented here from the code, not newly defined. The cited class and method are the source of truth. `BR-IAM-<NNN>` numbers are placeholders until rule IDs are assigned.

| ID | Rule | Enforced in | Source |
|---|---|---|---|
| BR-IAM-<NNN>.1 | A request needs `permissionName` (not blank), `justification` (not blank) and `durationMinutes` between 1 and 480. Otherwise 400 ("Requested duration must be between 1 and 480 minutes." for the duration). | backend | `PrivilegedAccessRequestCreateRequest` (`@NotBlank`, `@Min(1)`, `@Max(480)`), `PrivilegedAccessService#request` (`MAX_DURATION_MINUTES`) |
| BR-IAM-<NNN>.2 | `MANAGE_PRIVILEGED_ACCESS` can never be requested: 400 "This permission cannot be requested through privileged access — it must come from a standing role." | backend | `PrivilegedAccessService#request` (`SELF_ESCALATION_GUARD_PERMISSION`) |
| BR-IAM-<NNN>.3 | The permission must be granted by at least one role. Otherwise 400 "\"<name>\" is not a recognized permission." The scope (PLATFORM or ORGANIZATION) is worked out on the server from the roles that grant it. The client never sends a scope or organization id. | backend | `PrivilegedAccessService#resolveScope`, `PrivilegedAccessRequestCreateRequest` javadoc |
| BR-IAM-<NNN>.4 | An ORGANIZATION-scope request requires the requester to be an active organization member: otherwise 400 "You must belong to an organization to request this permission." The request is tied to that organization. | backend | `PrivilegedAccessService#request` |
| BR-IAM-<NNN>.5 | A new request is PENDING. The request is recorded in the request's audit trail (`REQUESTED`) and in the audit log (`PRIVILEGED_ACCESS_REQUESTED`). | backend | `PrivilegedAccessService#request` |
| BR-IAM-<NNN>.6 | Organization-scope review (list, approve, reject, revoke) requires **standing** `MANAGE_PRIVILEGED_ACCESS` in the caller's organization (seeded for `ORG_ADMIN`). A temporary grant can never provide it, because that permission cannot be requested. | backend | `OrganizationSelfService#listPendingPrivilegedAccess` / `#approvePrivilegedAccess` / `#rejectPrivilegedAccess` / `#revokePrivilegedAccess`; `RbacSeeder` |
| BR-IAM-<NNN>.7 | An organization administrator only sees and decides requests of their own organization: another organization's request returns 403 "That request does not belong to your organization". An unknown id returns 404. | backend | `PrivilegedAccessService#requirePendingRequestInScope`, `#revoke` |
| BR-IAM-<NNN>.8 | Nobody can approve or reject their own request (403 "You cannot approve your own request." / "You cannot reject your own request."). | backend | `PrivilegedAccessService#approve`, `#reject` |
| BR-IAM-<NNN>.9 | Only a PENDING request can be approved or rejected. Otherwise 400 "This request has already been decided." | backend | `PrivilegedAccessService#requirePendingRequestInScope` |
| BR-IAM-<NNN>.10 | On approval the grant expires at approval time plus the requested duration. The requester is notified, and the approval is audited (`APPROVED`, `PRIVILEGED_ACCESS_APPROVED`). | backend | `PrivilegedAccessService#approve` |
| BR-IAM-<NNN>.11 | On rejection the requester is notified, including the note as the reason if one was given, and the rejection is audited (`REJECTED`, `PRIVILEGED_ACCESS_REJECTED`). | backend | `PrivilegedAccessService#reject` |
| BR-IAM-<NNN>.12 | An approver can revoke a request that is PENDING or an active grant. Otherwise 400 "This request is no longer active." The revocation is audited (`REVOKED`). | backend | `PrivilegedAccessService#revoke` |
| BR-IAM-<NNN>.13 | A requester can revoke only their own request (otherwise 403), and only while it is PENDING or an active grant (otherwise 400 "This request is no longer active."). | backend | `PrivilegedAccessService#revokeOwn` |
| BR-IAM-<NNN>.14 | The decision note is optional for approve, reject and revoke. | backend | `PrivilegedAccessDecisionRequest`, `OrganizationController`, `PrivilegedAccessController` |
| BR-IAM-<NNN>.15 | An APPROVED request past its expiry is shown with `effectiveStatus` EXPIRED. | backend | `PrivilegedAccessService#toDto`, `PrivilegedAccessRequestDto` javadoc |
| BR-IAM-<NNN>.16 | An active ORGANIZATION grant satisfies that permission's checks inside the same organization only. An active PLATFORM grant satisfies platform permission checks. | backend | `OrganizationSelfService#requirePermission` / `#requirePermissionOnMember`, `PermissionAuthorizationManagerFactory` |
