# Search quality and speed report (C70)

Generated by `SearchQualityReportTest` on PostgreSQL 16.13 (Ubuntu 16.13-0ubuntu0.24.04.1) with pg_trgm and pgvector 0.6.0.

Test set: 12 products and 24 knowledge articles (English and Spanish), 40 queries (28 English, 12 Spanish).

**Embedding model: the test model (stub, word hashing).** No real model could be downloaded in the build environment. Semantic and hybrid figures therefore show the pipeline working, not the quality a real multilingual model gives; the similarity threshold and chunk size must be tuned again with the real model.

## Speed

Index for the measurement: the test set plus 2000 synthetic articles, 1000 synthetic products and 10000 synthetic tickets (13036 records, 7036 embedded passages). Each of the 40 queries ran 10 times after a warm-up, signed in as a customer with tickets, measured inside the backend (search service call, including the database and the HTTP call to the embedding service).

| Search | p50 | p95 | max | Target p95 |
|---|---|---|---|---|
| Keyword | 17.0 ms | 273.7 ms | 309.3 ms | under 500 ms |
| Hybrid (stub model) | 55.0 ms | 291.9 ms | 344.2 ms | under 800 ms |

The hybrid figure excludes a real model's own time to embed the query. A small multilingual model on CPU typically adds tens of milliseconds; this was **not measured** because no real model was available. The backend gives the model 400 ms (app.search.semantic.timeout-ms) and falls back to keyword results after that.
